# Errors, crashes, and release-blocking severity

Audit for U2-P6-15. Commit `main` after #241 plus this change, macOS arm64.

## Severity criteria

| Level           | Meaning                                                                                                                                                                                                | Release rule                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| **S1 blocker**  | Silent data loss or corruption; a failed save shown as saved; a crash or hang at startup or on ordinary input with no message and no way back; private data in a log or a file the user did not choose | Must be fixed before any beta is published.                        |
| **S2 major**    | A feature is unusable but data is safe; an error with no stated next step; a crash that a restart fixes without losing data                                                                            | Fix, or an owner-approved deferral written into the release notes. |
| **S3 minor**    | Wrong or confusing text, a rare workaround-able fault                                                                                                                                                  | Track. May ship.                                                   |
| **S4 cosmetic** | Visual polish                                                                                                                                                                                          | May ship.                                                          |

## Reproducible crash scenarios

| ID    | Scenario                                                                                                                                                                                                                                  | Result before                                                                                                            | Fix and result now                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ERR-1 | Open a workspace whose database was last used by a newer app (a migration the app does not know). Repro: copy a workspace to a throwaway `HOME`, add a row with version 999 to `_sqlx_migrations`, run the packaged app with that `HOME`. | **S1**: the app panicked at `main.rs` and exited with code 101 in under a second. No window and no message.              | Startup failure now shows a native error dialog ("This workspace was last opened by a newer version... Your data has not been changed.") and exits with code 1. Observed on the rebuilt packaged app: the process stays alive while the dialog is up and prints the same message to standard error. The dialog was not captured visually, and in one run the process ended on its own after 30 seconds without a click (cause not determined). The data file was not modified. |
| ERR-2 | A page throws while rendering (a bug, or a record in an unexpected shape).                                                                                                                                                                | **S2**: nothing caught it, so React unmounted the whole window to blank. Saved data safe; document drafts are journaled. | A boundary around the page area (`RouteErrorBoundary`) shows "Something went wrong on this page", **Try again**, and **Go to Home**, and clears on navigation. The sidebar keeps working. The text is fixed: the error itself is never shown (see below). `tests/unit/routeErrorBoundary.test.tsx`.                                                                                                                                                                            |
| ERR-3 | Ordinary invalid input to any create or update: empty, NUL bytes, right-to-left override, 100,000-character strings, impossible dates, unknown time zones, malformed JSON, SQL and HTML payloads.                                         | Not tested as a set.                                                                                                     | `hostile_input_tests` sends 24 such values through issues, milestones, documents, habits, check-ins, events, and dashboards: no panic, most refused with an error, the database passes `integrity_check`, and the table named in the SQL payload still exists.                                                                                                                                                                                                                 |

## Audit results

| Requirement                            | Result                                                                             | Evidence                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No silent data loss                    | Pass                                                                               | Failed saves keep the entered values and say so; the autosave journal keeps drafts ([Recovery](RECOVERY.md)); failed imports reject before any write, one transaction ([Security](SECURITY.md), input matrix); migrations roll back on failure ([Data model](DATA_MODEL.md)).                                                                                         |
| Clear user-facing errors               | Pass with the startup fix                                                          | Feature specs assert visible error text with a retry for issues, habits, mood, calendar, dashboard, documents, and imports. Startup failures were silent before ERR-1.                                                                                                                                                                                                |
| No sensitive data in logs              | Pass                                                                               | No `console.*` in the frontend (tested); Rust prints 25 fixed-text `eprintln!` lines with the error value, never record text ([Privacy](PRIVACY.md)); the page-error screen never prints the error. The startup dialog shows the technical error text to the person at the screen; it is not logged to a file or sent anywhere, but a database path can appear in it. |
| Recoverable states                     | Pass                                                                               | Retry actions on failed loads and saves; Try again and Go to Home on a page error; drafts offered back after a reload.                                                                                                                                                                                                                                                |
| Safe handling of invalid records       | Pass                                                                               | Unknown document versions open read-only with an error and the saved content untouched; unusable dashboard layouts fall back to defaults and are left unchanged (existing specs).                                                                                                                                                                                     |
| Behavior after failed imports          | Pass                                                                               | A rejected file changes nothing, with a readable reason (input matrix).                                                                                                                                                                                                                                                                                               |
| Reliable startup error messages        | Pass for a newer database; not exercised for a corrupt file or missing permissions | ERR-1. Other startup failures go through the same dialog with the generic next step.                                                                                                                                                                                                                                                                                  |
| No crashes from ordinary invalid input | Pass                                                                               | ERR-3. Production `unwrap`, `expect`, and `unreachable!` calls were reviewed: each follows a check that makes it unreachable (for example the date parts in `projects::valid_date` are verified to be 4, 2, and 2 ASCII digits before they are parsed).                                                                                                               |

| ERR-6 | S3       | A panic inside a Tauri command ends only that call in the current Tauri version; a repeated one would show as a failed load. No ordinary-input panic was found.                                                                         | Accepted.                                                                          |
